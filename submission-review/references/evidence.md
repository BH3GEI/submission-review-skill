# 证据从哪里找

最硬的证据是文件比对：交上去的应用和智能体里预置的文件是否相同。其余来源用来说明模型实际做了多少事。

| 证据来源 | 看什么 | 典型信号 |
| --- | --- | --- |
| 智能体包 | 预置文件、写死的题目名、复制逻辑 | 代码里写死题目全称；用 `copytree` / `copyfile` 把整个目录拷到输出目录；有放成品的目录（如 `snapshots/`、`official/`、`deterministic/`）；注释或日志里写着 "no model calls" |
| 交上去的应用 | 与预置文件的重合 | 逐字节相同；同一道题的多个阶段交的是同一份应用；第 1 阶段就带着后面阶段才要求的功能 |
| 选手自带的运行记录 | 模型的思考和工具调用 | 模型写的文件没有进入最终提交；模型尝试读 `/workspace/tests`，以及读到了什么 |
| 平台后台（只读） | 提交与运行列表、最终选定的是哪份提交、agent.zip 的 sha256、运行时长、工具调用次数、token 用量和成本 | 某个阶段没有任何模型调用；运行时长和工具调用次数远低于同题其他选手。初赛中两份复制成品的提交，两道题合计只花了 0.06 元和 0.33 元；但也有干净的选手总花费不到 2 元，所以成本低只是线索，不是证据 |
| 隐藏测试 | 与选手自带测试逐行比对 | 大部分测试文件 80% 以上的行相同，辅助函数和结构也一致，并且被用来驱动修改 |
| 公开题面 `requirements.yaml` | 判断一段内容是不是只复述题面 | 按钮名、报错文案、示例账号都能在题面里逐字找到，说明只是照题面写的 |

## 使用注意

- **先扣公共代码。** 官方空白模板、官方 runtime、公开开源框架（及其比赛截止前的历史版本）都放进 `--baseline`。初赛时有两位选手一开始看起来重合约 80%，扣掉公开框架后共有的行数是 0。
- **测试的时序要向组织方确认。** 初赛中，隐藏测试是在智能体退出后才复制进 `/workspace/tests`，所以智能体代码里"读测试目录"的设计不会生效。但智能体退出后，平台会启动选手生成的应用来跑测试，这时应用可能读得到测试目录；如果应用把读到的内容随产物带回，选手就能拿到测试。看到选手持有与隐藏测试高度相同的测试时，要考虑这条来源。
- **注释和文档不是证据。** 选手代码里"这里不读取测试""这只是通用模板"之类的说法，都要顺着代码确认。说法与代码不符时，作为加重情节写进记录。
- **自动审查的报告要先核对对象。** 初赛中出现过分析报告写的是别人的代码、内容乱码或缺失的情况。
