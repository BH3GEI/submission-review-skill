# 比赛说明示例：ARC-Bench（2026 年 10 月）

本文件用来回答 SKILL.md 第一步的五个问题，同时给出两轮复核中的参考案例，帮助校准判断。审查别的比赛时，照这个结构另写一份。

## 比赛形式

- 选手提交一个智能体包（zip）。平台在容器里运行它，按题面生成 Web 应用：一道是 GitHub 协作平台，一道是在线表格。
- 应用生成后，平台用 Playwright 隐藏测试评分。分数综合通过率和模型花费。

## 五个问题

1. **布局**
   - 初赛：每位选手的目录是 `NNN-<选手>-<提交 id>/`，里面有 `agent/agent.zip` 和 `applications/*.zip`，每道题或每个阶段一份。
   - 决赛：每位选手的目录是 `<选手>-<提交 id>/`，里面有已解压的智能体目录（名称不固定）、`applications/<题>-<id>.zip` 和 `metadata.json`。`metadata.json` 记录排名、分数、通过率、成本和包的 sha256。
   - `origin` 在两种布局下都能自动找到智能体包。
2. **起点**
   - 初赛：官方空白模板。
   - 决赛（hackathon-evolution）：继承本队初赛的应用，题面是在初赛基础上的演进需求。继承的应用不算赛前答案。但用包里带的、离线做好的新版本替换继承应用，算硬编码。
3. **隐藏测试**
   - 智能体退出后，测试才被复制到 `/workspace/tests`，智能体运行期间读不到。
   - 之后平台启动生成的应用跑测试，这时应用进程可能读得到测试目录。
   - 跑 `signals` 时加 `--test-path /workspace/tests ARCBENCH_TESTS_DIR`。
4. **反馈**
   - 应用 zip 里带着 `.arc/playwright-report.json`（官方测试报告，含失败信息）和 `.arc/stdout.log`。
   - 选手可以下载已评测的工作区。从这些报告里总结出来的规则和数值，属于平台反馈。
5. **口径**（组织方确定）
   - 只抓硬编码，不抓预置知识。
   - 结论分为通过、通过（附注）、不予通过、待定。
   - 同源分组默认只保留排名最高的账号；明显的一人多号（如十几个账号跑同一套未公开的代码）可以整组不予通过。
   - 自动审查工具是 [code-philia/hackathon-anti-cheat](https://github.com/code-philia/hackathon-anti-cheat)，它一票否决的总判决不沿用。

## 公共代码基线

- 官方空白模板
- 官方运行时 `arcbench_agent_runtime`
- octos-org 公开的 octos-arc 项目，含比赛截止前的历史版本
- 公开的 OpenCollab 框架

## 参考案例（不含选手身份）

### 初赛

| 情形 | 数据 | 结论 |
| --- | --- | --- |
| 按题目名选出预置应用，复制交上去 | 各阶段应用与预置文件重合 99%–100%，三个阶段交的是同一份；两道题合计成本只有几毛钱 | 不予通过 |
| 空壳模板加提示词，应用由模型生成 | 重合 1%–28%，重合的是脚手架；有一位选手总花费不到 2 元，但应用是干净的 | 通过 |
| 两位选手基于同一个公开框架 | 不扣基线时约 80%，扣掉以后为 0 | 不作为同源 |
| 自带测试与隐藏测试 80%–100% 的行相同，并用来驱动修改 | 测试来源未能查清 | 待定 |
| 有读测试目录的设计，但运行时目录为空 | 日志显示 `no *.spec.ts` | 通过（附注） |
| 应用把测试期间收到的请求记录下来带回 | 带回的文件中，分界标记之后是隐藏测试的流量 | 通过（附注） |
| 两组账号各 4 个，组内智能体包 sha256 完全相同 | 逐字节相同 | 每组保留排名最高者，其余待定（代码同源） |
| 16 个账号跑同一套未公开的代码 | 报名邮箱随手填 | 整组不予通过 |

### 决赛

| 情形 | 数据 | 结论 |
| --- | --- | --- |
| 把平台给的继承应用挪走，换成包里离线做好的版本 | 两道题共 183 个源码文件与包内成品逐字节相同；每题约 3 分钟跑完；成本 0 元 | 不予通过 |
| 在继承应用上由模型分组修改；包里带有从自己早先官方测试报告整理出的三条验收规则，其中一条是题面没写的具体数据值 | 包内没有应用代码，重合约 2%；版本历史 5 次和 4 次提交，新增约 1900 行和 3500 行；那个数据值最多影响 60 个测试中的 1 个 | 通过（附注） |
| 预置了公式、网格等模块，再加上继承的初赛应用 | 不扣起点时重合约 37%；逐字节相同的只有基础设施，约占 14%；用起点作基线后，本轮新增部分与包内重合 0.3%；本轮按需求逐项提交 18 次和 7 次 | 通过（附注） |
| 应用压缩包在约 72MB 处被截断 | 用 bsdtar 恢复文件，再用 `history --export-end` 从 `.git` 恢复完整源码 | 材料问题，不影响结论 |
